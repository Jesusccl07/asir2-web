Arranque y parada de la instancia
El fichero de parámetros, los tres estados de una CDB y cómo arrancar y parar PDBs.


  
El fichero de parámetros

  
Para arrancar la instancia, Oracle necesita leer el fichero de parámetros de inicialización, ubicado en $ORACLE_HOME/dbs. Puede ser de dos tipos:

  

    
📝
init$ORACLE_SID.ora
Texto plano, editable a mano. No se puede incluir en los backups de RMAN. Hay que tenerlo en el propio sistema para arrancar con él.

    
💾
spfile$ORACLE_SID.ora
Binario, no editable directamente pero sí visualizable. Permite arranque remoto y guarda los cambios de ALTER SYSTEM. Existe desde la 9i.

  

  
i
¿Dónde está?Si no lo encuentras, conéctate como SYS y ejecuta show parameter spfile.


  
Los tres estados de una CDB

  

    
    
Cada estado añade un paso más: de solo memoria, a conocer los ficheros, a tenerlos abiertos.

  

  
EstadoQué ocurre

    
NOMOUNTConexión a los archivos de control, lectura de parámetros, creación de la SGA, arranque de procesos background y apertura del fichero alert.

    
MOUNTLos procesos se asocian a los archivos de la BD. Se abre el fichero de control y se obtienen los nombres de datafiles y redo log.

    
OPENSe abren datafiles y redo log. Se comprueba la consistencia y, si hace falta, SMON inicia la recuperación. La BD queda accesible a todos.

Arranque y parada de PDBs

  

    
🔌
Abrir una PDB
alter pluggable database freepdb1 open; desde la CDB, o startup; conectando directamente a la PDB (si ya está MOUNTED).

    
🔒
Cerrar una PDB
alter pluggable database freepdb1 close; desde la CDB, o shutdown conectando directamente a ella.

  

  
Modo de aperturaQué permite

    
OPENModo READ WRITE, acceso completo.

    
OPEN READ ONLYSolo lectura.

    
RESTRICTEDSolo usuarios con privilegio RESTRICTED SESSION.

    
OPEN UPGRADEPara ejecutar scripts de actualización.

    
OPEN FORCECierra con ABORT y reinicia.

  

  
alter pluggable database all open; abre todas las montadas (con EXCEPT (pdb1, pdb2) se pueden excluir algunas).

Asegurar las cuentas de administrador
SYS y SYSTEM, sus contraseñas por defecto y cómo cambiarlas.

  

    
👑
SYS change_on_install
Propietario del diccionario de datos. Se usa para arrancar/parar la BD y modificar sus componentes.

    
🛠️
SYSTEM manager
El DBA "por excelencia". Tareas administrativas habituales: alta de usuarios, tablespaces, etc.

  

  

    
¡Cámbialas siempre!change_on_install y manager son contraseñas públicas conocidas por cualquiera.

    
SYS ≠ SYSTEMSYS es dueño del diccionario; SYSTEM es para el trabajo diario del DBA.

  

  
Cambiar las contraseñas

  
-- conectado como system
alter user sys identified by "contraseña";
alter user system identified by "contraseña";

Configurar herramientas cliente
Qué necesita cualquier programa para conectarse, y cómo darlo de alta en Oracle Client o SQL Developer.

  

    
🧩
Cadena de conexión
Host, puerto y SERVICE_NAME (el nombre real de la BD), tal como aparecen en tnsnames.ora.

    
🔌
Driver específico
El software que habla el protocolo Oracle Net: el propio Oracle Client, o el driver JDBC/ODBC integrado en una aplicación.

  

  
Oracle Client frente a SQL Developer

  

    
ORACLE CLIENT
Se instala; incluye SQL*Plus, SQL Developer y otros. Hay que configurar su tnsnames.ora.

    
SQL DEVELOPER SOLO
No requiere instalación: la cadena de conexión se da de alta directamente en el propio programa.

El diccionario de datos
Tablas base y vistas, los prefijos USER_/ALL_/DBA_/V$, y algunos ejemplos clásicos.

  
El diccionario de datos es el conjunto de tablas y vistas que almacena toda la información sobre los objetos de la BD: definiciones, espacio ocupado, integridad, usuarios, privilegios, roles, auditoría, etc.

  

    
Tablas base codificadas
    
      
  • •Se crean automáticamente al crear la BD.
    • 
      
  • •Contienen de verdad la información del diccionario.

    
Vistas legibles
    
      
  • •Se crean al lanzar catalog.sql.
    • 
      
  • •Dan acceso legible a las tablas base.

Trazas en usuarios y ficheros de log
El alert log, las trazas de los procesos background y cómo activarlas en una sesión de usuario.

  
El alert_<SID>.log

  
Registra en orden cronológico errores internos, operaciones de administración (STARTUP, SHUTDOWN, CREATE, ALTER…) y cambios en parámetros principales.

  
select * from v$diag_info where name like '%Alert%';
select * from v$diag_info where name = 'Diag Trace';

  
Trazas de los procesos background

  

    
¿Qué proceso genera cada traza?

    

    

  

  
Trazar una sesión de usuario

  

    
👤
Desde el propio usuario
Activa su traza con DBMS_MONITOR (necesita grant execute de SYS primero).

    
🕵️
Desde un administrador
Con el SID y SERIAL# de V$SESSION, puede activar la traza de otra sesión.

  

  
-- desde el propio usuario (SYS le dio permiso antes)
exec dbms_monitor.session_trace_enable(waits=>true, binds=>false);

-- desde un administrador, sobre otra sesión
select sid, serial#, username from v$session;
exec dbms_monitor.session_trace_enable(session_id=>SID, serial_num=>SERIAL#);
